# 开发与实验流程

1. 从 [优化索引](../optimization/INDEX.md)选定一个任务，确定行为边界、基线提交和可观察的正确性条件。
2. 检查 `git status --short`，从合适提交建立短期分支。方案若依赖另一实验分支，记录精确父 SHA；不要仅凭名称推断继承。
3. 做小范围修改，先运行与改动相关的静态检查、构建和 Smoke Test。正式入口、评分逻辑和数据语义有变化时须单独审查。
4. 在允许的节点提交正确性门槛测试，再运行多轮配对性能实验。保存原始日志、运行元数据与失败结果，不覆盖旧记录。
5. 将实验结果登记到 [实验索引](../experiments/INDEX.md)。报告同时列出预处理时间、搜索时间、端到端时间、ROC10 和错误 query 数；注明测试覆盖范围。
6. 审查后合并稳定成果。正式 100-query 日志须来自同一次完整运行；提交脚本的 `--dry` 只检查合法性，不代替正式提交或人工审核。

登录节点仅进行轻量管理。编译与小规模调试在集群允许的测试节点进行，完整运行通过 Slurm；实际节点和资源限制以组委会当前规则为准。正式预处理不得在 `prologue.sh` 计时开始前执行。对正在运行的作业，先确认其源码、二进制、输入输出和工作目录，再考虑任何目录调整。
